# รายงานความคืบหน้าโปรเจกต์ DIRECTOR AI

รายงานสถานะปัจจุบันของโครงสร้างโปรเจกต์ในแพ็กเกจ `com.pearparinya.directorai`

## 1. สถานะการเชื่อมต่อระบบ (Connections & Integrations)

- **AI Service (Google Gemini):**
  - **สถานะ:** ใช้งานได้จริงผ่าน App-to-App Integration
  - **รายละเอียด:** ไม่ได้เชื่อมต่อผ่าน API/SDK โดยตรง แต่ใช้วิธีส่งคำสั่งและรูปภาพผ่าน Android Intent (แชร์ข้อมูล) ไปยังแอปพลิเคชัน Gemini (`com.google.android.apps.bard`) โดยตรง ซึ่งผู้ใช้ต้องติดตั้งแอป Gemini ไว้ในเครื่อง
- **AI Service (Google Flow / Google Veo):**
  - **สถานะ:** ใช้งานได้จริงผ่านการส่งคำสั่งเข้า Web Browser
  - **รายละเอียด:** คัดลอก Prompt สำหรับสร้างวิดีโอลง Clipboard และใช้ Intent เปิดหน้าเว็บ `https://flow.google.com` บนเบราว์เซอร์ (แนะนำเป็น Chrome)
- **ระบบอัปเดตอัตโนมัติ (GitHub API):**
  - **สถานะ:** เชื่อมต่อใช้งานได้จริง (Real Implementation)
  - **รายละเอียด:** ฟังก์ชัน `checkForAutoUpdateFromGitHub` เรียก API ของ GitHub (`https://api.github.com/repos/pearparinya/director-ai/releases`) ผ่าน HTTP GET เพื่อตรวจสอบเวอร์ชันใหม่และแจ้งเตือนให้ดาวน์โหลดไฟล์ APK แบบอัตโนมัติ
- **Database & Storage:**
  - **สถานะ:** ใช้งานได้จริงผ่าน Local Storage
  - **รายละเอียด:** ไม่ได้ใช้ฐานข้อมูลภายนอก ข้อมูลถูกเก็บผ่าน `SharedPreferences` สำหรับบันทึกสถานะการทำงานต่างๆ และเก็บรูปภาพ Character Master ลงในระบบไฟล์ (Internal Storage)

## 2. ความคืบหน้าของหน้าจอและฟีเจอร์ (UI & Features)

- **โครงสร้างหน้าจอและคลาส:**
  - **`MainActivity.kt`**: เป็นคลาสเดียวและหน้าจอเดียวของแอปพลิเคชันในตอนนี้ ควบคุมการทำงานทั้งหมด
  - **การสร้าง UI:** ไม่ได้ใช้ไฟล์ XML หรือ Jetpack Compose แต่ใช้วิธีเขียนโค้ดสร้าง UI ขึ้นมาโดยตรง (Programmatic UI) เช่น `LinearLayout`, `TextView`, `Button`, `ScrollView`
- **ฟีเจอร์หลัก (ทำงานเชื่อมโยงกันครบถ้วนภายใน MainActivity):**
  - ระบบตั้งค่าภาพต้นแบบ (Character Master Setup): เลือกรูปภาพจากเครื่องเพื่อใช้เป็นหน้าตาตัวละคร (กวิน, รินลดา, มายด์)
  - ระบบเลือกโครงเรื่องและหมวดละคร (Step 1): สุ่มเลือกชื่อเรื่องจากข้อมูลจำลองที่เตรียมไว้
  - ระบบสร้าง Prompt อัตโนมัติ: ดึงข้อมูลโครงเรื่อง เหตุการณ์ เสื้อผ้า มารวมเป็นข้อความคำสั่งตามกฎ 9:16 และ Silhouette Lock
  - ระบบส่งเรื่องให้ Gemini (Step 2 & 3): แชร์ Prompt และรูปภาพไปที่แอป Gemini
  - ระบบเชื่อมต่อไป Google Flow (Step 4): คัดลอกวิดีโอ Prompt แล้วเปิดหน้าเว็บ
  - มีระบบเสียงแจ้งเตือน (ToneGenerator) และแสดงเวลาแบบเรียลไทม์

## 3. จุดที่ยังทำไม่เสร็จหรือควรแก้ไขต่อ (Missing Links & Next Steps)

- **การเชื่อมต่อ AI แบบ Native (Direct API Integration):**
  - ตอนนี้ต้องพึ่งพาแอป Gemini ภายนอก ควรพิจารณาเชื่อมต่อกับ Gemini API โดยใช้ `Google Generative AI SDK for Android` (หรือ REST API) เพื่อรับ-ส่งข้อมูลโดยตรงภายในแอปเลย จะช่วยให้ประสบการณ์ใช้งานลื่นไหลขึ้นและไม่ต้องสลับแอป
- **ข้อมูลจำลอง (Mock Data) ที่ยัง Hardcode:**
  - โครงเรื่อง หมวดหมู่ ชื่อเรื่อง (`titleBanks`, `storyCategories`) และลำดับเหตุการณ์ฉาก (`storyBeat`) ถูก Hardcode ไว้ในโค้ดทั้งหมด (Mock/Stub)
  - **สิ่งที่ควรแก้ไข:** ควรดึงข้อมูลจาก Database ภายนอกหรือให้ AI เป็นคนสร้างโครงเรื่องและเหตุการณ์แบบไดนามิก แทนที่จะวนลูป 10 เหตุการณ์ซ้ำๆ
- **สถาปัตยกรรมโค้ด (Code Architecture):**
  - โค้ดทั้งหมด (UI, Logic, File Handling, API call) รวมอยู่ใน `MainActivity.kt` เพียงไฟล์เดียว ทำให้ไฟล์ใหญ่และดูแลยาก
  - **สิ่งที่ควรแก้ไข:** ควรแยกสัดส่วนโค้ด (Refactoring) ตามหลักการ MVVM โดยแยก UI (ควรเปลี่ยนไปใช้ XML หรือ Jetpack Compose), แยก ViewModel จัดการ Logic, และ Repository จัดการข้อมูลและ API
- **การจัดการ UI:**
  - การเขียน UI ผ่านโค้ดแบบเดิม ทำให้ยากต่อการออกแบบและปรับแก้ ควรนำไปสู่ระบบ Layout ที่เป็นมาตรฐานเพื่อให้ปรับแต่งหน้าจอและรองรับขนาดหน้าจอได้ดีกว่านี้
